# DiLink-Auto

*Бұл қазақ тіліндегі аударма. Түпнұсқа ағылшын нұсқасы: [README.md](../../README.md).*

Телефон қолданбаларын көлігіңіздің кірістірілген экранына толық сенсорлық басқарумен көшіріңіз. Ашық бастапқы код, Google Services қажет емес.

Бұл DiLink-Auto жобасының **түпнұсқа репозиторийі** ([andersonlucasg3/dilink-auto-android](https://github.com/andersonlucasg3/dilink-auto-android)). 2026 жылдың қарашасында оған ұзақ жұмыс істеп келген [ID-VerNe/dilink-auto-android](https://github.com/ID-VerNe/dilink-auto-android) форкінің 252 коммиті қайта біріктірілді; ол upstream үнсіз қалған кезде жобаны өміршең ұстап тұрды. Даму **қытайлық телефон ROM-дары мен BYD DiLink бас блоктарына** бағытталған күйде жалғасуда, **базалық DiLink 4.0** үшін арнайы баптау жасалған — ол әлсіз аппаратта «слайд-шоудан» қолдануға жарамды деңгейге көшеді.

## v0.18.0-dev бастап не өзгерді

Тармақтану нүктесі (`84df5cb`, upstream/main) мен ағымдағы `main` арасындағы эволюцияның қысқаша баяны. Әр тармақ жоспар емес, нақты коммиттерге сәйкес келеді; толық хронология [docs/progress.md](../progress.md) ішінде.

### 1. Тікелей VD ағындық архитектурасы

Телефон бұдан былай бейне, сенсор немесе дыбысты реле арқылы өткізбейді. VD сервері `9638` (бейне), `9639` (енгізу) және `9640` (дыбыс, екі жақты келіссөзден кейін ашылады) порттарын байланыстырып, қабылдағышпен тікелей сөйлеседі. Бұл кадр сайын 4 сокет + 2 процесс контекстінің ауысуын алып тастап, 2 сокет + 0 ауысу қалдырады. Телефон таза оркестраторға айналады: қол алысу және мүмкіндіктерді келісу, VD өмірлік циклі (`VD_PORTS_BOUND`) және бас блок логтарын маршруттау. Протокол `FrameCodec.readFrameBlocking()`, `MessageType.VD_PORTS_BOUND` және `AudioPayload` алды, ал `VirtualDisplayClient` тек өмірлік циклге дейін қысқартылды.

### 2. Базалық DiLink 4.0-ді баптау (негізгі жұмыс)

Жоғарыдағы жабдыққа қарсы:

- **Кодтау өлшемі 1920x1080-мен шектелді.** Бұрын телефон IME қиылуын болдырмау үшін VD-ны физикалық пиксельге дейін үлкейтетін (1080x2340 → кодтау 2340x1658); бұл 439-дың аппараттық декодтау шегінен асып, бағдарламалық декодтауға түсіп, 8x A53 1080p-ден жоғары H.264-ты бір таңбалы fps-пен ойнататын. VD өлшемін кодтау өлшемінен ажырату арқылы түзетілді — VD үлкейтілген күйде қалады (IME түзетуін сақтайды), ал кодтау өлшемі көлік хабарлаған көрініс аймағына ілесіп, 1920x1080-мен шектеледі.
- **Битрэйт 8 Mbps → 4 Mbps.** 2.4 GHz көлік ортасында тұрақты өткізу қабілеті 5-15 Mbps өлшенді, сондықтан 8 Mbps ешқандай қор қалдырмады. Бейімделгіш шегіну де қатайтылды: ең төменгі шек 1.5 Mbps, 2 с қалпына келу терезесі, 0.5 Mbps қадамдар (бұрын ол 8 мен 2 Mbps арасында тербелетін).
- **Кадр жиілігі 30 → 24 → 20.** Әдепкі мән енді 20 fps (кадрға 50 мс). #71 мәселесін қараңыз: 2.5 сағат навигация телефонды қыздырды, ал кадр жиілігін төмендету — VD үлкейту шегінен кейінгі екінші қысымды босату клапаны.
- **TextureView → SurfaceView.** Adreno 505-тің кадр сайынғы толық экранды GL композициясын айналып өтеді (кадрға шамамен 2-5 мс). `outputSurfaceValid` қақпасы декодер навигация кезінде жасырылып/көрсетілгенде жойылған бетке рендерлеуді болдырмайды.
- **Ағын басымдықтары.** A53-те үлкен ядролар жоқ, сондықтан жоспарлау кеңестері маңызды: кодтау/декодтау/сокет ағызу ағындары `THREAD_PRIORITY_URGENT_DISPLAY`, ал `LifeWriter` — `THREAD_PRIORITY_BACKGROUND` қолданады.
- **Лог әдепкілері.** Release құрастыруларында `carLogEnabled` әдепкі бойынша өшірулі (бұрын қосулы еді, лог кадрлары бейнемен 2.4 GHz арнасы үшін бәсекелесетін); `ConcurrentLinkedQueue.size()` (O(n)) `AtomicInteger` болып өзгерді.
- **Ажырату кезінде AppIconCache тазалау.** ~80-150 PNG бұрын 16 GB eMMC-де мәңгі жинақталатын (5-9 MB heap). Жаңа `clear()` `handleDisconnect` ішінен шақырылады, ал `prepareAll` `Semaphore(4)`-пен параллель декодтап, аралық битмаптарды қайта өңдейді.
- **`Debug.getPss()` жойылды.** Бұл ескірген binder шақыруы әр қосылымда орындалып, A53-те 100-500 мс кетіретін; енді ол тек құлау кезінде жиналады.
- **`@Immutable AppTileData`.** `AppInfo` `ByteArray` тасиды, бұл `AppTile`-ты өткізілмейтін етіп, әр `appList` қайта тағайындалғанда толық қайта композициялауға мәжбүрлейтін. `iconPng`-ны шығаратын өзгермейтін қаптама торға қайта композициялауды өткізуге мүмкіндік береді.

### 3. API 28 бас блок үйлесімділігі

Нақты BYD блогында (`k65v1_64_bsp`, Android 9 / API 28) `MediaCodecInfo.isHardwareAccelerated()` (API 29+) `NoSuchMethodError` лақтырып, процесті өлтіреді. Спекулятивті аппараттық декодер таңдаушысы жойылып, `createDecoderByType` қайтарылды (`REGULAR_CODECS` аппараттық декодерлерді бірінші орынға қояды; BYD-де ол `OMX.qcom.video.decoder.avc` таңдайды). `minSdk` `app-server` және `protocol` үшін 24 → 26 болды, NewApi lint қақпасы қайта қосылды. `am display move-stack` (API 29+) енді API 26-28 үшін `SDK_INT`-ке байланысты шектеледі және shell қатесін сәттілік деп есептеудің орнына логқа жазады.

### 4. UI және өзара әрекеттесу

- **Навигация панелі қайта жасалды:** Eject (ажырату) / Home / Back-ке дейін қысқарды. Хабарлама батырмасы, соңғылар панелі, сағат және желі ақпараты төрт модульдегі өлі кодпен бірге жойылды (көлік жағындағы `NotificationScreen`, `RecentAppsState`; телефон жағындағы `NotificationService`; `FOCUSED_APP` / `APP_SHORTCUTS` / `NOTIFICATION_*` хабарлама типтері). **Бұл код базасында хабарламаларды жіберу жоқ.**
- **Қолданбаларды бекіту:** қолданба белгішесін ұзақ басу Pin to Top / Unpin береді, SharedPreferences-те сақталады.
- **Қолданбалардың рұқсат тізімі:** жаңа `AllowlistScreen` пайдаланушыға қай қолданбалар көлікке жіберілетінін таңдауға мүмкіндік береді; таңдалмағандар `sendAppList` кезінде сүзіліп, сымдағы жүктемені және көліктің белгіше декодтау жұмысын азайтады. Кең таралған навигация қолданбалары бірінші іске қосуда алдын ала таңдалады. Ауыстыру `ACTION_ALLOWLIST_UPDATED` жібереді, сондықтан жұмыс істеп тұрған қызмет тізімді қайта жібереді және көлік торы тірі жаңарады.
- **Портретті қолданбаларды қолдау:** динамикалық DPI есептеу (`VideoConfig.calculateOptimalDpi`) портретті қолданбаларды (Amap, WeChat) ландшафтты VD ішінде жіңішке жолаққа сығуға жол бермейді; IME сессия соңында қалпына келтіріледі (бұрын телефон linkpc IME-ін ұстап қалатын); көпсаусақты инъекция индексі түзетілді.
- **Көлік жағында іске қосу DPI-ін қайта анықтау:** қол алысуға `dpiOverride` өрісі қосылды (0 = автоматты, [120, 480] = пайдаланушы мәні), оны көліктің `startup_dpi` параметрі басқарады және екі бағдарда да жіберіледі. 1280x800-де тым кіші әдепкі DPI-ді түзетеді.
- **Түс токендері және қаріп ірілендіру:** шашыраңқы `Color.Gray` / `0xFF888888` `onSurfaceVariant`-ке көшірілді, қайталанған қате қызылдары біріктірілді, белгілер 12sp → 14sp. "WiFi Direct Mode" "WiFi ADB Mode" болып өзгертілді; көлік жағындағы `adb tcpip` мәтіні жойылды.
- **Айналдыру кезіндегі қара экранды түзету:** `onCarViewportChanged` күйді CONNECTING-ке қойып, айналдыру кезінде VD-ны қайта орналастырады, бірақ ағындық орналасу қақпасы `isConnected` қолданған (~2 с қайта орналастыру үшін false), сондықтан `CarShell` `CarLaunchScreen`-ге қайтып, `TextureView` композициядан шығып, жаңа бет декодерді қайта іске қоса алмады. Қақпа енді `state == CONNECTING && appList.isNotEmpty()` қабылдайды, айналдыру кезінде ағындық орналасуды (және оның бейне күту қабатын) сақтайды.

### 5. Сессия тұрақтылығы

Белсенді сессияны қайта қосылу әрекеті ешқашан өлтірмейді — бұрын Wi-Fi шлюзінің қайталауы немесе қолмен қосылу жұмыс істеп тұрған сессияны өлтіретін. Қайта қосылу циклі 3 қатарынан ADB сәтсіздігінен кейін тоқтайды. TCP ADB телефон IP-сі өзгергенде қайта қосылады және USB қолжетімсіз болғанда автоматты түрде TCP ADB-ге шегінеді.

### 6. PipelineServer тұрақтандыру

`VirtualDisplayServer` (1287 жол, 9 ағын, 2 кезек) `PipelineServer` (бір ағын, 0 кезек) болды: кадр сағаты → GL рендер → кодтаушы ағызу → TCP жазу, табиғи ағын бақылауымен (қатып қалған TCP жазу келесі `eglSwapBuffers`-ті блоктайды). Сондай-ақ түзетілді: уақытша EGL контекстінде жасалып, кейін жойылған GL текстурасы (құбыр ағыны 0 текстурасын байланыстыратын); интерактивті емес shell шыққанда өлтірілетін `app_process` (`shellBackground` арқылы түзетілді, ол shell ағынын тіркелген күйде ұстайды); және физикалық панельді қалпына келтіру тәртібі (shell жабылғаннан кейін `input keyevent 224` шақыратын).

### 7. Диагностикалық лог қосқышы

Параметрлер → Debug диагностикалық лог қосқышын алды. Өшірулі кезде дискіге жазу нөлге тең. Күй көлікке `LOG_TOGGLE` деректер хабарламасы арқылы жеткізіледі және #72 мәселесінен бастап әр қол алысудан кейін автоматты түрде синхрондалады, сондықтан көлік логы қайта қосылуда үнсіз қалпына келтірілудің орнына телефон қосқышына ілеседі. Әдепкілер: debug/pre-release құрастыруларында қосулы, release-те өшірулі; пайдаланушының нақты таңдауы сақталады.

### 8. Жеңілдетілген қытайша UI

Клиент те, сервер де `values-zh-rCN` / `values-zh` жеткізеді. Қолданба жолдары ағылшын, португал (BR), француз, орыс, беларусь, қазақ, украин, өзбек және қытай тілдерінде бар.

### 9. Код денсаулығы

SRP/DRY аудиттері мен рефакторингтерінің бірнеше раунды: модульаралық ортақ тұрақтылар (`AppPrefs`, `AppTargets`, `VdDeploy`, `VdDeployArgs`, `WifiGatewayIp`, `AppIconLimits`) және бөлінген әріптестер.

- **`protocol-core` / `protocol`:** `NioWriter` (тайм-аутпен сокет-арнасына spin жазу), `BackoffPolicy` (параметрленген экспоненциалды шегіну), `DecodeLivenessTracker`, `ConnectionFactory`, `ConnectionKeepAlive`, `UsbAdbKeyStore`, `Ipv4Validator`, `AppIconLimits`; өлі `UsbAdbConnection` коды жойылды.
- **`vd-server`:** `AsyncSocketSender`, `AudioEncoderSelector`, `ProcessWatchdog`, `VideoEncoderSelector`, `PortAcceptor`, `ActivityDumpParser`, `VdDisplayHealer`.
- **`app-client`:** `ConnectionService` жеңілдетілді; `ShizukuVdDeployer`, `ShizukuNav`, `ClientNetworkMonitor`, `CarAppInstallHost`, `AllowlistRepository`, `SessionState` бөлінді; `InputInjectionService` ескірді.
- **`app-server`:** `CarConnectionService` ~407 жолға дейін қысқарды; күй машинасы `CarSessionCoordinator` (9637/9638/9639/9640 көп арналы күй машинасы және қайта қол алысу), `CarAdbTracker` (USB/TCP ADB бақылау) және `CarAppListReceiver` (қолданба тізімі және белгіше қауіпсіздік шектеулері) болып бөлінді.
- **`app-desktop`:** `AppIconLimits`, `DecodeLivenessTracker`, `BackoffPolicy` тұтынады, протоколдың соңғы примитивтерімен үйлестірілген.

### 10. VD ағып кетуін түзету, идемпотентті тазалау, қара экранды өзін-өзі емдеу

**Түпкі себеп:** әр қайта қосылу бір VirtualDisplay-ды ағызып кететін. Ескі код `pkill -9` қолданатын, ол JVM shutdown hook-ты өткізіп жібереді, сондықтан `PipelineServer.cleanup()` ешқашан орындалмайтын — VD босатылмай, физикалық панель өшірулі қалып, `screen_off_timeout` параметрі жоғалатын (суреттеме кодтың өзі жазған `2147483647` сентинелін сақтаған). Бірнеше қайта қосылудан кейін көлік экраны қарайып кететін.

**Түзету (12 файл):** тоқтату сұранысының сентинелі (`/sdcard/DiLinkAuto/stop-request`), оны қозғалтқыш күзетшісі тұтынып, қалыпты жолмен шығып, толық `cleanup()` орындауы үшін (ART қарапайым SIGTERM-де shutdown hook-тарды орындамайды); `pgrep -f` негізіндегі зонд (toybox `pkill -0`-ді қабылдамайды); `kill -9` қосалқы жолы pid-ті `pkill -f` орнына `pgrep -f` арқылы табады (соңғысы қаптама shell-ді де өлтіріп, ADB нәтижесін оқылмайтын етеді); `AtomicBoolean` `cleanupGuard`, 7 шақыру орны `cleanupSession()`-ды қайта-қайта орындамауы үшін (бір ажырату бұрын 9 «Force-waking physical display» шақыратын); екі жақта да `waitForVdServerExit()`, екі қозғалтқыш бір VD мен порттар үшін ешқашан бәсекелеспеуі үшін; `PhoneDisplayRestorer` `NonCancellable`-мен өз процесс өмірлік аясында; қайта реттелген `cleanup()`; `DisplayPowerController.restoreSetting()` мән тексеруі; және `BlackScreenDetector` (`BLACK_SCREEN_SUSTAIN_MS = 3000`) `protocol-core`-ға көшіріліп, көлік пен десктоп оны бөліседі, `rehandshakeForBlackScreen()` сессия басына ең көбі бір әрекетпен бекітілген.

Регрессия автоматикасы `scripts/` ішінде: `verify-blackscreen-fix.sh`, `e2e-reconnect-cleanup.sh`, `verify-reconnect-cleanup.sh` (нақты десктоп интерфейсі арқылы 32 тексеру; соңғы толық жүгіріс 32/32, 2m48s).

### 11. Windows қабылдағышы `:app-desktop`

Бас блоктан басқа, сол протокол қабылдағыш ретінде **Windows бағдарламасын** қолдайды: телефон экраны ДК терезесіне көшіріледі, ал тінтуір сенсорға айналады. Модуль `app-desktop/` ішінде (Kotlin/JVM + Compose Desktop 1.6.2, JDK 17) және `protocol-core`-ды қайта пайдаланады — телефон жағында өзгеріссіз.

- **Транспорт:** телефонға тікелей үш TCP қосылымы — 9637 (басқару + деректер), 9638 (бейне), 9639 (енгізу) — көліктегідей, релесіз.
- **Орналастыруды бөлу:** қол алысу жауабындағы `connectionMethod` VD серверін кім орналастыратынын шешеді. Shizuku болса, мұны телефон жасайды; әйтпесе десктоп жергілікті `adb.exe`-пен орналастырады (`connect` → ескі қозғалтқышты өлтіру **және оның шынымен шыққанын күту** → `exec app_process`), бұл `config.json` ішінде `"dev_mode": true` қажет етеді.
- **Декодтау:** JavaCV/FFmpeg бағдарламалық декодтауы плюс D3D11VA аппараттық декодтауы, аппараттық іске қосылу кезінде құласа немесе нөл кадр шығарса автоматты шегінумен.
- **UI:** үш навигация беті — Mirror / Apps (лаунчер) / Display (DPI-ді қайта анықтау, аппараттық декодтау қосқышы, "Apply and reconnect", ояу ұстау, телефонның физикалық экраны).
- **Өзін-өзі емдеу:** 10 с тұрақты қара экран автоматты түрде қайта қосылады, процесс басына ең көбі екі рет.
- **Конфигурация және логтар:** `%APPDATA%\DiLinkAuto` (`config.json` / `desktop.log`), `DILINK_DESKTOP_HOME` арқылы өзгертуге болады; `DILINK_ADB` adb жолын орнатады.

```bash
# Self-contained app-image (bundled JRE): copy build/compose/binaries/main/app/DiLinkAuto
./gradlew :app-desktop:createDistributable

# Headless probe: validates handshake/VD/fps only; without Shizuku set DILINK_DEV_MODE=1 for ADB deploy
app-desktop --probe
```

> Күйі: Shizuku жолы көлік жағымен сәйкеседі; **ADB орналастыру жолы нақты құрылғыда әлі тексерілмеген**. Модуль релиз активтеріне кірмейді (оның JavaCV/FFmpeg тәуелділігі GPL, ал бұл жоба MIT).

### 12. Юнит-тесттер және қауіпсіздікті күшейту

**Тест қамтуы:** екі модульде мүлдем тест бастапқы жиыны болмаған (`vd-server`-де `src/test` жоқ, `protocol`-дің іші бос). `8157c86`-дан бастап барлық 6 модульге JUnit4 юнит-тесттері қосылды, бұрын тексерілмеген ең қауіпті логиканы қамтыды (протокол кадрлау, ADB криптографиялық примитивтері, VD орналастыру аргументтері, бейімделгіш битрэйт, shell дәйексөз қақпасы, нұсқа қақпалары, орнату күйін жіктеу, құлау есебінің форматы). Мінез-құлықты сақтайтын «тестілеу тігістерінің» тағы бір раунды 44 қосымша жағдай қосты. Бүгінде репозиторийде 6 модульде 1,200+ `@Test` жағдайы бар (JUnit4 + kotlinx-coroutines-test, Robolectric/Mockito/MockK жоқ; Android модульдері `isReturnDefaultValues=true` және қолмен жазылған фейктер қолданады). Тізімдеме, бекітілген модульаралық инварианттар және ашық мәселелер [docs/IMPLEMENTATION_REPORT_TESTING.md](../IMPLEMENTATION_REPORT_TESTING.md) ішінде.

**Көршілес тораптарды күшейту (`a7d2b72`):** бұрын кез келген сокет көршісі сенімді деп есептелетін — 6 байттық дұрыс емес кадр телефон процесін немесе shell-UID VD серверін өлтіре алатын. Барлық бес декодер енді шикі `getX()` алдында `require()` тексереді; оқу корутиндері `Throwable` ұстап, себебін логқа жазып, өлудің орнына ажыратады; `MAX_PAYLOAD_SIZE` 128 MB-тан 16 MB-қа төмендеді және `NioReader` буферінің қатты шегі бар, ол кадр шекараларында қайтарылады.

**VD арнасын авторизациялау (`8601fb1`):** 9638/9639 порттары бұрын сол Wi-Fi-дағы кез келген хостты қабылдап, кез келгенге сенсор енгізуге және shell ретінде `am start` / `pm uninstall` орындауға мүмкіндік беретін. Енді олар тек қазір қызмет көрсетіліп жатқан қабылдағыштың қосылымдарын қабылдайды; қабылданбаған көршілер жабылады, ал сервер күтуді жалғастырады.

**Shell дәйексөзі (`5eae3e7`):** `VdDeploy` пәрмен жолдары `shellQuote` арқылы өтеді, сондықтан көрші басқаратын жолдар `sh`-қа ешқашан жалаңаш жетпейді.

**Десктоп (`1f6836a`):** қол алысу жауабындағы `adbPort` / `jarPath` қолданылмас бұрын тексеріледі (бұрын олар тікелей орналастыруға берілетін, яғни кез келген көршіден еркін код орындау); adb еншілес процестері енді ағып кетпейді.

**Көлік сессиясы (`bc2634c` / `35d7821`):** сессиялар буын ысырмасын қолданады, `cleanupGuard` желі өзгеруі жолымен ерте тұтынылмауы үшін; қара экраннан қалпына келтіру енді декодерде `stop()` шақырмайды (ешкім оны қайта іске қоспайтын, сондықтан қалпына келтіру жолы мәңгілік қара экранды кепілдейтін).

**Релиз жеткізу тізбегі:** релиз keystore бұрын коммиттелетін; енді ол тек сілтемеленеді, ал қолтаңба құпиялары CI-де (git тарихы әлі тазартуды қажет етеді). CI енді PR кодын self-hosted раннерлерде іске қоспайды (`9517205`) және қолтаңбасыз / шамадан тыс жұқартылған APK пен жетім артефактілер шығармайды (`efde81f`). Барлық жұмыс ағындары GitHub-hosted `ubuntu-latest`-те жүреді.

## Ағымдағы функция күйі

**Жұмыс істейді:**

- H.264 бейне көшіру, әдепкі 20 fps, CBR 4 Mbps, Main профилі (базалық DiLink 4.0 үшін бапталған; жоғары деңгейлі блоктарда да жұмыс істейді)
- Дыбыс көшіру: AAC-LC 48 kHz стерео, 128 kbps, арнайы TCP қосылымы (9640) арқылы, 150 мс джиттер буфері, 46.875 fps-те тұрақты тыныштық толтыру, екі жақты `FEATURE_AUDIO` мүмкіндік келісімі, клиентте сақталған дыбыс қосқышы
- Толық сенсорлық енгізу (көпсаусақ, шымшу арқылы масштабтау)
- Қолданба лаунчері: іздеу, алфавит тәртібі, 64dp белгішелер, ұзақ басу мәзірі (жою, қолданба туралы, бекіту)
- Қолданбалардың рұқсат тізімі: көлікке тек таңдалған қолданбалар жіберіледі
- Көлік жағында іске қосу DPI-ін қайта анықтау (1280x800-дегі кіші әдепкі DPI-ді түзетеді)
- Бағдарға ілесу: көлік айналғанда VD қайта құрылады, портретті қолданбалар енді жолаққа сығылмайды
- Shizuku қолдауы: USB ADB-сіз VD серверін орналастыру және көлік қолданбасын үнсіз `pm install`-мен өзін-өзі жаңарту
- Көлік қолданбасын өзін-өзі жаңарту: телефон `versionCode`-ты салыстырып, көлік қолданбасын Wi-Fi ADB арқылы жаңартады
- Ағын кезінде телефон экраны өшірулі (батареяны үнемдейді); ажырату кезінде физикалық панель қалпына келтіріледі
- Бағытталған рұқсат онбордингі
- Жеңілдетілген қытайша UI және тағы 8 UI тілі
- Тікелей VD архитектурасы: телефонда реле жоқ; бейне, сенсор және дыбыс тікелей өтеді
- VD ағып кетуін түзету: сентинел негізіндегі әдепті тоқтату (толық `cleanup()`, `kill -9` тек тайм-аут қосалқы жолы ретінде), идемпотентті тазалау қорғанысы, VD шығуын күту
- Қара экранды өзін-өзі емдеу: көлік 3 с тұрақты қара экраннан кейін VD-ны қайта құрады (қайта қол алысу); Windows қабылдағышы сол детекторды 10 с терезесімен қолданады
- Windows қабылдағышы (`app-desktop`): көшіру терезесі, тінтуір сенсоры, қолданба лаунчері, DPI/аппараттық декодтау панелі, adb орналастыру, `jpackage` қолданба суреттемесі

**Жойылды (біріктіруге дейінгі upstream-ке қатысты):**

- Хабарламаларды жіберу (телефон хабарламалары → көлік экраны): навигация панеліндегі хабарлама батырмасы, хабарламалар тізімі және `FOCUSED_APP` / `APP_SHORTCUTS` / `NOTIFICATION_*` протокол хабарламалары жоқ
- Соңғылар панелі, сағат, желі ақпараты

**Іске асырылмаған:**

- Медиа басқару элементтері
- Навигация виджеттері (дыбыс көшіру толық)

**Белгілі шектеулер:**

- USB ADB жұмыс істеуі үшін Samsung Auto Blocker өшірілуі керек (Параметрлер → Қауіпсіздік → Auto Blocker → өшіру).
- Samsung батарея менеджментіне нақты босату қажет.
- Samsung Knox виртуалды дисплейге бірінші рет қатынасқанда қауіпсіздік сұранысын көрсетуі мүмкін.
- Телефон хот-споты қолмен қосылуы керек (Android 16 шектеуі).
- Декодерді қайта қосу жарысынан кейде визуалды ақаулар; келесі кілт кадр (~1 с) қалпына келтіреді.
- Ағын кідірісі жүктеме кезінде шамамен 100-200 мс.
- Кейбір қолданбалар экранды толтырмайды (жолақтармен / тек портрет). DiLink-Auto ландшафтты виртуалды дисплейді көшіреді, сондықтан ландшафтты қолдамайтын қолданбалар қара жолақтар көрсетеді — мұны қолданбаның өзі шешеді.
- API 26-28 блоктарында `DisplayControl` рефлексиясы сәтсіз болса, `cmd display power-reset` / `power-off` shell қосалқы жолы да API 29+, сондықтан физикалық панель қайтпауы мүмкін (ол үнсіз сәтсіздіктің орнына логқа жазады).
- Орнату барысы ағылшын емес UI тілдерінде көрсетілмейді: `InstallStatus.parse` локализацияланған күй жолдарын ағылшын ішкі жолдары бойынша жіктейді, сондықтан қытайша (және басқалары) `IDLE`-ге түседі. Тесттермен бекітілген, түзетілмеген ([C-6](../IMPLEMENTATION_REPORT_TESTING.md)).
- Көлік қолданбасының бірінші орнатуын шектен тыс нұсқа нөмірімен өткізіп жіберуге болатын: `readInstalledVersion` көлік қолданбасы жоқ кезде `"0"` қайтарады, сондықтан ендірілген `versionName` `0` / `0.0` / `0.0.0` «өзекті» деп салыстырылады. Ағымдағы `versionName` — `0.19.0`, сондықтан бұл іске қосылмайды ([C-5](../IMPLEMENTATION_REPORT_TESTING.md)).

## Қалай жұмыс істейді

1. **Хот-спотты қосыңыз** — телефонның Wi-Fi хот-спотын қосыңыз; көлік оған қосылады.
2. **Қосыңыз** — телефонды көліктің USB портына қосыңыз (немесе сол Wi-Fi желісіне қосылыңыз).
3. **Автоматты орнату** — телефон көлік қолданбасын Wi-Fi ADB арқылы орнатады (тек бірінші рет, бір басу).
4. **Автоматты қосылу** — төрт Wi-Fi TCP ағыны: басқару (9637), бейне (9638), сенсор (9639), дыбыс (9640, келіссөзден кейін ашылады).
5. **Қолданбаларыңызды пайдаланыңыз** — көлік лаунчерінен кез келген қолданбаны іске қосыңыз; ол телефонда жұмыс істеп, көлік экранында көрінеді және сенсор қабылдайды.

Телефон қолданбаларды виртуалды дисплейде іске қосып, оларды H.264-ке кодтайды, ол көлікке жіберіледі. Көлік экранындағы сенсор оқиғалары телефонға нақты сенсор оқиғалары ретінде қайта енгізіледі. Телефонның физикалық экраны батареяны үнемдеу үшін өшірулі қалады және дербес пайдалануға болады.

Архитектура, қосылу ағыны және дизайн шешімдері: [docs/architecture.md](../architecture.md).

- Бір бос USB-A порты (немесе сол Wi-Fi желісі)

**Телефон хот-споты қосулы болуы керек** — көлік оған қосылады. Жұптасу кодтары жоқ, Google тіркелгісі жоқ.

**Интернет қосылымы қажет емес.** DiLink-Auto телефон хот-споты арқылы жергілікті түрде ағындайды; телефон мен көлік тікелей сөйлеседі. Интернет тек телефоныңызда жұмыс істейтін қолданбаларға қажет.

## Орнату

APK-ны [Releases](https://github.com/andersonlucasg3/dilink-auto-android/releases/latest) ішінен жүктеңіз немесе өзіңіз құрастырыңыз:

1. **Құрастыру:** `./gradlew :app-client:assembleDebug`
2. **Телефонға орнату:** `app-client/build/outputs/apk/debug/app-client-debug.apk`
3. **USB жөндеуді қосыңыз** (Параметрлер → Әзірлеуші параметрлері)
4. **DiLink-Auto-ны ашыңыз** және барлық файлдарға қатынау онбордингін орындаңыз
5. **Хот-спотты қосып, көлікке қосылыңыз** — көлік қолданбасы бірінші іске қосуда Wi-Fi ADB арқылы автоматты түрде орнатылады

Көлік APK-сы мен VD серверінің JAR-ы екеуі де телефон APK-сының ішінде қапталған, сондықтан көлікке бөлек ештеңе орнатудың қажеті жоқ және көлік қолданбасын орнату интернетті қажет етпейді.

> **Қолтаңбаны жаңарту туралы ескерту:** debug қолтаңбасы бар құрастырудан ресми қолтаңбаға көшу сертификатты өзгертеді — **алдымен ескі пакетті өшіріңіз**, әйтпесе орнату `INSTALL_FAILED_UPDATE_INCOMPATIBLE` қатесімен сәтсіз болады. Толық релиз және қолтаңба ережелері: [docs/release.md](../release.md).

## Жоба құрылымы

Телефон APK-сы (`app-client`) көлік APK-сын (`app-server`) және VD серверінің JAR-ын (`vd-server`) ендіреді. Қабылдағыш алмастырылады: сол протокол көлікте (`app-server`) немесе Windows-та (`app-desktop`) жүреді.

```
DiLink-Auto/
├── protocol-core/  Pure-JVM shared library (frames, messages, constants, VD deploy sequence; no Android dependency)
├── protocol/       Platform adaptation (ADB, Android hooks, USB/TCP connections)
├── app-client/     Phone APK — orchestration, VD deployment, car self-update, app allowlist
├── app-server/     Car APK — UI, connection state machine, video decoder
├── app-desktop/    Windows receiver — mirror window, FFmpeg decoding, adb deployment, jpackage
├── vd-server/      VirtualDisplay server (compiled to a JAR, deployed by the phone)
├── scripts/        Automation (log verification, end-to-end reconnect/cleanup)
├── docs/           Documentation (multilingual entry point)
└── gradle/         Build system
```

| Модуль | Рөл | minSdk |
|--------|------|--------|
| `protocol-core` | Таза JVM ортақ протокол кітапханасы (Connection/NioWriter/NioReader/FrameCodec/Messages/AudioPayload/VdDeploy/BackoffPolicy/DecodeLivenessTracker/BlackScreenDetector) | — |
| `protocol` | Ортақ протокол кітапханасы (UsbAdbConnection, AdbProtocol, VideoConfig, ConnectionFactory, ConnectionKeepAlive, UsbAdbKeyStore) | 26 |
| `app-client` | Телефон қолданбасы (ConnectionService, ShizukuVdDeployer, ClientNetworkMonitor, CarAppInstallHost, AllowlistRepository, FileLog) | 29 |
| `app-server` | Көлік қолданбасы (CarSessionCoordinator, CarAdbTracker, CarAppListReceiver, AudioPlayer, VideoDecoder, CarShell, HomeScreen, PersistentNavBar) | 26 |
| `app-desktop` | Windows қабылдағышы (DesktopApp, DesktopConnectionService, VideoDecodePipeline, SwingVideoView) | — |
| `vd-server` | shell UID-і бар процесс (PipelineServer, AudioPipeline, AudioEncoderSelector, PortAcceptor, TouchInjector, GlPipeline, DisplayPowerController) | — |

## Құрастыру

```bash
# Build the phone APK (runs buildVdServer + embedServerApk, bundling vd-server.jar and app-server.apk into the client assets)
./gradlew :app-client:assembleDebug

# APK location:
# app-client/build/outputs/apk/debug/app-client-debug.apk  (phone, embeds the car APK)

# Unit tests (6 modules, JUnit4 + kotlinx-coroutines-test, no Robolectric/Mockito/MockK)
./gradlew :protocol-core:test :protocol:test :vd-server:test :app-desktop:test
./gradlew :app-client:testDebugUnitTest :app-server:testDebugUnitTest
```

JDK 17 және Android SDK (compileSdk 34) қажет. Release құрастырулары `RELEASE_KEYSTORE_PASSWORD` / `RELEASE_KEY_PASSWORD` қажет етеді (`RELEASE_KEYSTORE_FILE` / `RELEASE_KEY_ALIAS` міндетті емес); міндетті айнымалы болмаса, конфигурация кезеңінде сәтсіз болады, ресми пакеттің үстіне орнатуға болмайтын қолтаңбасыз APK үнсіз шығарылмайды. Keystore-тың өзі ешқашан коммиттелмейді.

Windows-та балама пәрмендер `.\gradlew.bat` қолданады.
